# UI 重构方案 · 2026-11

## 0. 结论先行

当前 UI 不是"丑"，是**信息密度失控 + 视觉噪音叠加**：

| 病灶 | 证据 | 后果 |
| --- | --- | --- |
| 容器套容器 | 13 个视图里 `.dash-section` → `.table-wrap` → `table`，设置页 10 张卡片纵向堆叠 | 屏幕被边框切碎，一屏只能看 2–3 组信息 |
| 卡片数量失控 | 仪表盘 8 个指标卡 + 16 张后端卡 | 1440px 宽下指标卡被压到 142px，数字换行；后端区纵向 1900px |
| 字号/字重过碎 | 11/12/13/15/20/24px 混用，粗体 700 遍地 | 没有层级，靠"加粗"制造重点，反而全无重点 |
| 状态文本直接铺在表格里 | 供应商表 STATUS 列塞整段 JSON 报错 | 单行高度 200px+，表格不可扫读 |
| 主题色被稀释 | 深色面板灰蓝、浅色面板灰白，边框与背景差 < 8% | 显脏、发灰，"大气"无从谈起 |
| 历史补丁层层叠加 | `style.css` 末尾有 MODERN UI LAYER / LAYOUT FIXES / 后续覆盖共 4 层 | 同一个组件被 3–4 处规则争夺 |

## 1. 设计方向

**Calm Console**：安静、克制、可信。像 Linear / Vercel 控制台，不像后台模板。

三条原则：

1. **一层容器就够** —— 页面 = 背景；分区 = 无边框分组 + 留白；只有真正可交互/可滚动的东西才配拥有边框。
2. **用留白和字重分级，不用颜色分级** —— 页面只有 1 个强调色（靛蓝），其余全部中性色。红/绿/黄只表示状态。
3. **数字优先** —— 指标数字 24–26px/600 tabular-nums，标签 12px 次级色；表格行高 44px 起，行内文字最多 2 行。

| 强描边 `--border2` | `#2b3441` | `#d5dbe4` |

| 次要 `--text2` | `#98a3b4` | `#5b6675` |

深色画布压到 `#0a0c11`，面板 `#0f1219`，靠**明度差**而不是描边来分层。

### 1.2 字号阶梯

| Token | 值 | 用途 |
| --- | --- | --- |
| `--fs-xs` | 11px | 表头、徽标、极次要 |
| `--fs-sm` | 12px | 标签、辅助说明 |
| `--fs-md` | 13px | 正文、按钮、输入 |
| `--fs-lg` | 15px | 分区标题 |
| `--fs-xl` | 20px | 页面标题 |
| `--fs-2xl` | 26px | 指标数字 |

字重只用 **500 / 600**。取消 700 与全大写（仅表头保留 uppercase + 0.04em 字距）。

### 1.3 形状与投影

- 圆角：控件 8 / 卡片 12 / 弹窗 16（原来 9/14/18 三套并存）
- 浅色卡片只用 1px 描边，无投影；深色卡片无描边用 `--bg2` 面 + 极淡投影
- 弹窗/浮层才允许 `--shadow-lg`

## 2. 页面级改造

| 页面 | 现状 | 改造 |
| --- | --- | --- |
| 仪表盘 | 8 卡挤一行；16 张后端卡 1900px | 指标 4×2 网格；后端改为**紧凑行卡**（图标/名称/状态/摘要），2 列，高度降至 ~1/3 |
| 供应商 | 左列表 + 右表格，STATUS 列撑爆行高 | 左列 320px 固定；状态文本 **2 行截断**（已有 title 全量）；行高上限 56px；错误的 JSON 不再撑开表格 |
| 后端 | 4 列大卡，15/16 未安装 | 同上紧凑卡；未安装卡片降饱和但仍可读 |
| 统计 | 指标卡被压到内容溢出 | 与仪表盘同一套指标卡；图表卡等高网格 |
| 设置 | 10 张卡纵向 3000px | 双列网格（宽卡跨两列），可视高度减半；分区标题贴顶 |
| 模型/质量/路由/健康/签到/归档/账号 | 表格 + 工具条 | 统一表头/行高/hover；工具条合并为一行，搜索框固定 220px |
| 全局 | 4 层 CSS 补丁 | **重写 `static/style.css`**，单文件单层，按「tokens → 基元 → 组件 → 页面」组织 |

## 3. 开发方案

### 3.1 交付物

1. `static/style.css` 全量重写（约 2000 行，替换 4220 行的四层叠加）
2. `templates/index.html` 仅做**结构性微调**（不改任何 `id` / `onclick` / 数据流）：
   - 样式版本号 `?v=` 更新
   - 设置页 3 张宽卡加 `span-2`
   - 仪表盘指标行加 `stats-row-hero` 语义类（已有）
3. `tests/check_css_coverage.py`：静态校验"模板里用到的每个 class 都有样式"
4. `docs/ui-redesign-2026-11.md`（本文）

### 3.2 不改的东西（红线）

- 所有 `id=`、`onclick=`、`data-i18n`、JS 函数名 —— 一行不动，避免功能回归
- 后端 API、数据结构
- 三种语言的 i18n key

### 3.3 校验流程

1. `python3 tests/check_css_coverage.py` → 必须 0 MISSING
2. `python3 tests/check_template_js.py` → 模板内联 JS 语法
3. 直接跑 `python3 tests/test_*.py` 全量（102 项）
4. Playwright 对 13 个视图 × 深/浅两套主题截图，逐页目检
5. `python3 -m compileall` + 服务重启后 `/api/version` 探活

### 3.4 风险与回滚

| 风险 | 处置 |
| --- | --- |
| 遗漏某组件样式 | 覆盖率脚本兜底（用到的 class 必须有规则） |
| 动态拼接 class（`'task-' + x`）误报 | 脚本忽略以 `-` 结尾的前缀片段 |
| 浅色/深色某一侧失真 | 两套主题都截图，不只看默认 |
| 需要回滚 | `git` 分支 `backup/pre-ui-2026-11-04` + tag 同名 + `~/dev/freework/.backups/openclaw-auto-manager-pre-ui-2026-11-04.tar.gz` |

## 4. 落地结果

- `static/style.css` 单文件 3901 行，572 个规则块，0 个未定义 token
- 覆盖校验：模板/内联 JS 使用的 **396 个 class 全部有样式**
- 13 个视图 × 深浅两套主题全部截图目检（1440×1000）
- 顺手修掉的 4 个真实 bug：
  1. 活动日志 `.recent-list` 是 `<ul>`，容器被当成了单行 flex，日志互相重叠
  2. `.key-toolbar-left input{width:200px}` 把 `type=checkbox` 也拉成 200px 宽
  3. `.profile-meta` 竖向 flex 把 badge 拉成整行灰条（Routes 页 "auto"）
  4. 签到页汇总文案用 `{token}` 占位，语言包却是 `{yes}`/`{no}`，前端一直显示原始占位符
- 模型页 LOCATIONS 列由「无限堆叠 chip」改为「前 3 个 + `+N`」，单行高度从 ~1000px 降到 ~85px
